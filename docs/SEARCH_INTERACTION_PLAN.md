# 全站搜索与选择交互统一规划

状态：规划，尚未完成全站改造。2026-10-20；当前应用基线 `6366899e`，另有本轮专属设置窗口的小修正。

## 目标与依据

采用 tapmodels 原作者现有的 React、Radix、shadcn、cmdk 和主题变量，统一搜索、选择及焦点规则。以同一交互规范覆盖页面筛选、单选、多选和远程补全，保留各业务的权限和保存语义。

已核对本地上游 `origin/main@5fdc0492` 与共同基线 `819ee2a7`。以下原作者实现没有差异，可作为改造依据：

- `web/src/features/logs/filters/filter-combobox.tsx`：按钮触发 `Popover + Command`，选中关闭，支持名称与 ID。该文件已被本地上一轮改动删除；从 Git 读取参考，把能力收敛到共享组件，不恢复页面专属的重复实现。
- `web/src/features/vm/detail-proxy-tab.tsx`：主动打开后搜索，`Command shouldFilter={false}` 使用代理业务的子串匹配，避免模糊匹配返回无关地址。
- `web/src/components/ui/{input,popover,command,dialog,select}.tsx`：继续作为视觉、弹层和键盘行为的基础。
- `web/src/features/proxies/proxy-bind-picker.tsx`：保留无代理/换绑分组、可用席位与明确的绑定操作。
- `web/src/features/logs/filters/identity-filters.tsx`：Session ID 补全已有 300ms 去抖、至少 2 字符查询规则。

## 当前问题

1. 新增的 `SearchSelect` 手工处理方向键、焦点和列表项，原作者其他入口使用 `Command`，两套生命周期并存。
2. 普通输入框聚焦就展开候选，遇到 Dialog 自动聚焦、Tab、点击弹层外部时容易出现自动展开、闪退和焦点回跳。
3. 搜索文本、选中的 ID、显示名称混在同一个输入值中；输入被清空时可能立即清掉业务选择，后台刷新和无匹配结果时含义不明确。
4. 页面各自用 `includes()`，有的搜索名称，有的还搜 ID/别名/地区，大小写和前后空格处理不一致。
5. 加载、无数据、无匹配、请求失败没有统一区分；标签、清除按钮、下拉宽度、中文提示也不一致。

## 统一交互规范

| 场景 | 统一方式 | 生效时机 |
| --- | --- | --- |
| 页面列表筛选 | `SearchInput`，搜索图标、明确标签、清除按钮 | 输入即过滤；清空恢复当前其他筛选条件下的列表 |
| 用户/分组/Key/模型/槽位/代理等单选 | 基于原作者 `Popover + Command` 的 `SearchSelect` | 点击或键盘主动打开，输入即筛选；点击或 Enter 确认后才修改所选 ID |
| 模型白名单、授权、批量分组等多选 | 保留列表/勾选结构，复用 `SearchInput`、匹配规则及 Command 列表能力 | 勾选更新表单草稿；沿用页面保存流程 |
| Session ID 等允许自由输入的补全 | 原作者输入框 + 候选提示结构，使用统一输入和状态样式 | 输入保留原文；候选是建议，不强制只能选候选 |
| 角色、协议、状态等固定枚举 | 现有 `Select` | 保留固定选项，无额外搜索框 |
| 全站页面跳转 | 保留现有 `CommandMenu` | 用户点击或按 Cmd/Ctrl+K 主动唤起 |

实体选择统一为原作者的“触发控件 → 搜索面板 → 确认选择”，不会再把已选值和正在输入的搜索词放在同一文本框里互相覆盖。搜索面板内输入立即显示结果，不增加“搜索”提交按钮。

### 焦点和展开

- 进入页面、打开普通表单弹窗时，不自动聚焦搜索或表单输入框，不展开候选。对话框容器接收必要的无障碍焦点，Tab 焦点留在对话框内，关闭后返回原触发控件。
- Tab 只移动焦点；单纯获得焦点不展开下拉。点击触发控件，或按 Enter、Space、向下键，才打开选择器。
- 用户主动打开选择器后，才聚焦其内部搜索输入框；主动唤起命令搜索时同理。
- 下拉内 Escape 先关闭下拉并返回触发控件，再按 Escape 才关闭父弹窗。点击外部关闭，不改变已选项。
- 重新打开显示当前选择与完整候选，查询词默认清空。选择单项后关闭；多选保持打开，便于连续勾选。
- 用户正在中文输入法组合输入时，Enter 不确认选项、不提交表单；组合输入结束后再匹配/查询。
- 清理散落的无条件 `autoFocus`、`onFocus -> setOpen(true)` 和互相争抢焦点的处理。按最新偏好，后续改造会将此前“创建 Key 聚焦名称”也收敛为普通弹窗规则。
- 登录、显式进入重命名/自定义时区、命令搜索等聚焦语义单独登记：只有用户刚刚主动进入编辑/搜索才允许聚焦，不因页面渲染或刷新抢焦点。

### 输入、筛选与数据

- 统一大小写不敏感的子串匹配，查询时去除首尾空格；保留输入框原文，尤其不在每个按键时 trim 中文组合输入。
- 共享匹配函数接收名称、ID 和调用方明确提供的关键词。用户可搜名称/ID及后端实际返回的邮箱；模型可搜模型 ID/显示名/别名；代理沿用原来的地址/名称/槽位/地区/时区字段。不会搜索或回显密码和完整密钥。
- 使用稳定 ID 表示选项，名称只是显示值。未确认的搜索词不改变选择；显式清除才清除选择。自由输入型 Session ID 保留自己的输入契约。
- 本地已加载列表立即匹配，不人为增加 300ms 延迟。服务端补全沿用 TanStack Query：300ms 去抖、取消过期请求、查询键包含搜索词和权限范围，旧响应不覆盖新结果。
- Session ID 保留至少 2 字符的既有接口规则。普通本地名称搜索允许 1 个中文字符；不把远程接口限制强加给所有搜索框。
- 数据源是否分页由接口决定；已加载的一页不能冒充全量搜索。现有全量轻量目录继续在客户端过滤，真正分页的实体才接入对应服务端查询，不为统一外观额外拉全量数据。
- 保持业务顺序。多选模型在匹配结果中将已选项置顶；代理的未绑定/换绑分区、可用性与禁用原因继续保留，不用模糊得分重新打乱。
- 页面筛选与“全部”选项统一；表单必填选择不显示“全部”。无匹配结果不清掉原选择，后台刷新不清空编辑草稿。
- 用户、Key、分组等相互依赖的条件继续由页面显式更新。例如更换日志用户时清掉不兼容的 Key；创建用户 Key 只查询该用户可用的分组。共享组件不推断、更不扩大权限。

### 视觉与状态

- 复用原作者 Input/Button/Command 的主题色、圆角、字重、焦点圈；常规高度统一 `h-9`，紧凑表格沿用明确的 `sm` 密度。
- 输入用途使用可见标签或可访问名称；提示统一为“搜索用户…／搜索分组…”。触发器未选时显示“选择用户”，筛选器显示“全部用户”。
- 面板默认与触发器同宽，受视口边界约束，内容高度统一并允许滚动；长名称省略/换行方式一致。
- 状态明确分为正在加载、暂无可选项、没有匹配结果、加载失败可重试、选项不可用。已有选择在重载期间保留名称。
- 模型白名单保留“已选 N 个”摘要，不恢复重复的已选标签列表；授权列表旁的倍率/RPM 输入保留为业务表单。

## 实施顺序与验收

1. **共享规范先落地。** 重构 SearchSelect、增加 SearchInput/匹配函数、统一普通 Dialog 默认焦点。先在套餐用户/分组、VM 分组和分组专属设置四个入口验收，确认不自动展开、不闪退、可连续选择。
2. **迁移单选入口。** Key、账务、日志、模型、代理、节点、槽位等调用点逐项接入。保持原 API 数据形状与权限范围，避免同时修改后端业务规则。
3. **统一文本搜索、多选和补全。** 处理独立 Input、白名单/授权搜索、Session ID、中文提示和密度；清理重复匹配与页面焦点补丁，不保留两套可执行旧方案。
4. **全站回归与交付。** 运行 TypeScript、改动文件 lint、现有相关 Vitest；共享匹配边界用少量有意义的测试覆盖，焦点/弹层在实际浏览器验收，随后本机 Docker 验收并按既有目标交付。

共同验收场景：

- 新开页面/弹窗不选中文字、不自动显示候选；Tab 经过搜索选择器不展开。
- 鼠标和键盘均可主动打开，输入中文/英文/ID 立即筛选；切换两个相邻搜索器不闪退。
- 输入法 Enter 不误选/误提交；方向键、Enter、Escape、Tab 可连续操作。
- 选择、显式清除、无匹配、恢复全部、关闭重开、后台刷新均不丢失有效选择或表单草稿。
- 远程输入快速变化、请求乱序、失败重试、关闭后响应返回均不显示错误候选。
- 单选确认仅触发一次回调；多选不自动关闭，选项与摘要一致；仅搜索不触发保存、绑定或套餐发放。
- 普通用户看不到越权数据；停用项、已删除项、空目录、无授权目录有正确状态。
- 深色/浅色、窄屏、长名称、Dialog 内 Popover、滚动和焦点返回都可用。
- 回归用户全局/分组/Key RPM、计费倍率、资源分组版本、模型白名单与原有保存接口，避免交互重构影响业务。

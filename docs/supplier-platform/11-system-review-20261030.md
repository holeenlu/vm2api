## 2026-10-30 运营代理池增量

超管 `/suppliers/proxies` 已改为独立代理池工作台，按供应商范围读取 `vendor_resources` 与统一 `proxy-pool` 的合并视图，展示协议、脱敏地址、认证存在性、池状态、启用状态、延迟、地区、质量评分和绑定席位。工作台支持新增、地址/认证编辑、单条和批量连接测试、质量检测、地区检测、启停以及归档；代理归档前检查绑定席位，不能把仍被账号使用的出口直接变成历史孤儿。

新增管理接口使用 `/api/admin/vendors/proxies/:id/{probe,quality-check,geo,enable,disable,archive}`，批量接口使用同一资源前缀的 `POST /probe`、`/quality-check`、`/geo`。所有响应继续脱敏；供应商资源与池状态同步，地址变更会回写绑定 VM 的出口配置并在运行环境需要时重新加载。无效状态先校验，不能先关闭统一池再返回错误。

单元用例文件位于 `test/unit/`，HTTP 用例位于 `test/e2e/`。S 编号是本轮缺陷证据索引，不替代完整验收矩阵。

凭据静态加密复核：`secure.mjs` 只有配置平台数据库密钥时才加密；未配置时仍保留既有存储方式。已修正“代理始终加密保存”的界面和资料措辞；本轮不擅自更改密钥配置或重写历史凭据。

## 2026-10-30 账号池交互、详情侧栏与状态筛选复核

供应商和超管继续复用同一套账号池组件，但列不是无条件相同：供应商自有账号池不显示“供应商”列，超管保留该列用于跨供应商识别，表格最小宽度随角色调整。账号名称是独立复制按钮，复制成功由统一 toast 反馈；详情只从操作列的信息按钮进入，避免名称点击与详情动作冲突。

状态筛选按业务状态分类：异常账号包含授权被取消（包括 `OAuth access token has been revoked.` 映射的认证异常）和已删除/归档账号；停用账号仅指正常账号被暂停调度的 `paused` 资源，不再把归档账号混入停用统计或停用筛选。归档筛选仍可单独查看历史账号。

详情侧栏已按参考控制台补齐展示顺序和字段：账号邮箱/名称标题、代理与地区、账号来源、授权方式、权重、总请求与 Token、创建时间、分组/备注、RPM/TPM、成功率、实时并发、当前状态、账号级冷却、平台配额、模型限制、数据快照和清除冷却。标题优先采用真实账号邮箱，未返回详情数据时回退列表身份；没有新增账号或代理数据读取范围。

## 并行交付边界

账号池、开户、代理选择、结算工作台和详情侧栏均以当前 `origin/main` 组合树为准；本轮补充账号名称复制、供应商端列布局、详情标题/入口以及状态筛选口径。后续修改这些共享组件时，应重跑 S01–S14、TC26、状态分类单测及对应工作台回归，尤其检查新开户与新结算路径没有绕过身份、归档和付款边保护。

## 验证口径

本轮 backend 相关回归包含原供应商 API、两条账务边、Claude/Codex 调度、授权终端与新增缺陷用例；前端检查包含能力展示、共享结算操作、时间与 TPM 语义和四语覆盖。命令、结果、输入树和远端 CI 在交付证据中记录，历史 10 号文档的通过数字不代替本轮结果。

原终端测试在 macOS 无 `/proc` 时错误要求数值 CPU/内存，本轮改为 Linux 继续要求数值、非 Linux 允许设计中的 unknown；不是跳过用例。真实 Linux 客体登录不由命令生成及票据单测替代。

无 Schema 迁移、无历史数据库清理；旧权限错误产生的绑定和范围需要按范围盘点后独立处理，本轮不修改生产数据。旧付款、账单、审计和已应用迁移保持。付款仍仅登记线下事实，不执行转账。

# 业务流程与状态机

更新于 2026-10-30，描述当前真实流程；后续目标单列，不把方案图当作已运行代码。

## 下级开户

有效供应商/成员 → 一级 + create_child → 幂等键命中则校验业务摘要并返回原主体 → 当前父级范围、child_limit、共享资源上限、能力子集 → 事务新建独立用户/主体/成员/合同/审计 → 返回脱敏记录。调用者不能指定现有 user_id；不同参数复用 key 为冲突。空选择继承父级，旧空范围也叠加父级当前限制。

## 账号与 VM 生命周期

账号开户 → 同事务账号资源/VM 资源 → 固定默认配置预配运行时 → 绑定自有代理和分组 → 实际启动 → 返回 runtime_boot 并进入授权。重复开户返回原配对，不拿新请求中的代理重新绑定旧账号。配对缺失返回需要修复的错误，归档不可重放。

账号和 VM 资源成对 `active ↔ paused → archived`；VM 内部初态可 provisioning。供应商暂停独立记录，不覆盖操作员 schedule_off。归档后两条资源只读，不能继续授权或启动；历史用量、合同、账单与审计不删除。VM start/stop 调用运行时，不再只改资源状态。

## 停用、撤权与恢复

仅超管治理供应商主体。状态/范围更新进入 DB；业务写入重读当前身份和父级，Claude/Codex 选号与可用性展示读取 DB 当前供给资格。磁盘 vendor_disabled 仅为投影，不是唯一事实。恢复不清除手动暂停、无凭据、冷却或已归档状态。父级停用后子级不能新建资源或处理付款。

供应商登录终端只运行 `cli-node auth login`，票据单次且限时；签发、连接、输入和会话期间复核身份。授权导入/换码在完成外部调用后、提交前再校验归属。多进程策略 CAS、完整在途任务排空与 claim/nonce 仍待实施。

## 用量到结算

已定价成功请求摘要 → 同事务 vendor_usage_facts → 与未重复记录的留存日志统一查询 → 选择单周期有效合同 → 预览 token（周期、合同、汇总、账号明细）→ 校验未变化并生成冻结账单 → 付款方审核 → 分次登记已完成的线下付款。平台→一级和一级→二级分别按真实 payer 验权。

- 相同周期重试返回原单，不按当前合同重算；非作废周期不能重叠。
- `review → confirmed → partial → paid`；零金额确认即 paid，重复确认幂等。
- `draft/review/confirmed → void` 仅限未付款，必须理由；保留历史，同合同同周期作废记录不能被覆盖。
- 付款需要独立 key、正金额和凭证，重复 key 同内容只记一次，冲突或超付拒绝。
- confirmed 表示付款方审核；没有新增收款方签收或争议流程。
- 超管可以看下游账单，不能代替一级登记下游付款；一级需超管显式授予 settlement.pay。

## 待实现的流程

跨合同周期自动拆分、付款冲正/争议及导出、失败预配的外部文件/运行时补偿、统一 revision/claim/nonce 与任务取消仍未完成。不能靠覆盖旧账、改已应用迁移、删除生产数据或隐藏按钮伪装完成。

门户下游结算现使用15分钟预览令牌 → 幂等草稿 → 有付款能力者确认 → 分次付款登记。逐请求分配防止重复；迟到用量可补单；作废释放本单占用。自然日账期和冻结价格/汇率/调整依据见04及统一实施记录。

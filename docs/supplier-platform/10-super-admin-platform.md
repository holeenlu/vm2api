# 超管供应商平台（2026-10-29）

这是上一轮移植记录。2026-10-30 的完整复核及进一步修复以 [复核矩阵](11-system-review-20261030.md) 为准；历史验证数字保留，不代表本轮验收。

## 来源和实施选择

本轮基于 `holeenlu/sub2api` 本地干净 `main@0276190e775b369319acc18bc1c120a4469a71ae` 对照移植用户指定的五个超管供应商后台入口。来源包括 `frontend/src/views/admin/VendorsView.vue`、`features/vendor/api.ts` 以及 `VendorManagement.vue`、`VendorEditor.vue`、`AccountWorkbench.vue`、`ProxyWorkbench.vue`、`UsageWorkbench.vue`、`SettlementWorkbench.vue`。以上为交互、业务边界和页面信息架构参考；实现为 vm2api 原生 React/Node/SQLite 代码，没有复制 Vue 组件或另建数据库、登录体系。sub2api 工作区未修改。

| 功能 | 对照决定与落地 |
| --- | --- |
| 供应商管理 | 采用概览卡、搜索/状态筛选、名单、平台/分组/资源上限和关联跳转。沿用供应商主体、成员和单一 vendor 登录角色，原子创建登录账号和一级主体，支持编辑、停用及归档；全局价格独立位于“结算设置”。 |
| 账号池 | 采用供应商范围筛选、账号状态/额度/用量/操作表格；复用现有供应商开户流程生成配对 VM、绑定供应商自有代理和分组。授权及进一步调度配置进入现有超管 VM 详情。新增、重命名、暂停/恢复、归档均操作同一资源。 |
| 代理管理 | 复用供应商代理资源及统一代理池，新增、重命名、暂停/恢复、归档；输出脱敏地址，密钥仍由原凭据字段按平台密钥配置保存。暂停同步关闭统一池代理及其关联 VM 的出口资格；入池失败回滚供应商代理资源，避免留下失联记录。 |
| 用量统计 | 采用供应商、账号、模型、日期维度及每日统计；读取共享请求用量，删除供应商日期统计在无事实时回退到不受日期限制的累计快照旧路径。 |
| 结算对账 | 采用预览、生成、确认、登记付款、详情与作废操作；沿用现有供应商合同、结算、付款和审计表。平台向一级供应商结算，包含直属下级用量；下游账单在超管侧只读，一级供应商继续负责自己的下游结算。 |

仅移植明确要求的五个入口。附图其他“分组供给”“操作审计”独立后台页面未扩入本轮；现有业务操作仍写入原审计表。2026-10-30 起，账号额度与状态统一在“供应商平台 → 账号池”展示，与供应商门户共用账号展示组件和脱敏投影；移除重复“服务提供商”页面及专用接口。

## 导航与权限

超管侧栏新增“供应商平台”分组，依次为：

1. `/suppliers/suppliers`：供应商管理。
2. `/suppliers/accounts`：账号池。
3. `/suppliers/proxies`：代理管理。
4. `/suppliers/usage`：用量统计。
5. `/suppliers/settlements`：结算对账。

`/suppliers` 重定向管理页。入口由 `/api/panel/me.views` 的 `suppliers` 控制，仅 super_admin 获得；路由和服务端分别检查。普通管理员、用户及供应商不能调用超管供应商接口。跨页关联采用 `vendor_id` 查询参数；资源修改根据服务器查出的资源 owner 确定供应商，伪造不一致的 vendor_id 拒绝。

运营管理菜单为“总览 → 统计 → 使用记录 → 用户 → API 密钥 → 充值记录”；账号池统一在供应商平台分组中。

## 同一数据链

- 主体与登录：`vendors`、`vendor_members`、`users`、`vendor_capabilities`；新建失败整体回滚，不残留登录账号。
- 账号及代理：`vendor_resources`，账号通过配对 VM 资源的 `runtime_vm_id` 指向运行时；代理通过 `pool_proxy_id` 关联统一池。
- 用量：成功且已定价请求随 `UsageLogsRepo` 写入 `vendor_usage_facts`，与原请求摘要处于同一事务，以 source_request_id 去重。不把失败、平台自建 VM 或未定价请求伪装为供应商可结算费用。
- 升级前仍保留的 `usage_logs` 经账号/VM 映射补充查询，已写入事实的请求不重复累计；无需迁移或批量回填历史日志。新事实独立于日志保留期保存；已经在升级前清理的历史日志无法重建。
- 同一个 `vendorUsage` 查询供超管统计、供应商日期统计和结算预览使用，明确 UTC 开始时间包含、结束时间不包含。跨范围供应商参数拒绝。未定价请求单独计数并阻止结算。
- 结算：`vendor_contracts`、`vendor_settlements`、`vendor_payments`、`vendor_audit_events`。供应商账单读取同一结算记录、冻结用量快照及已付金额/付款凭证；二级供应商也能看到一级供应商生成的上游账单。
- 停用供应商给其账号 VM 增加独立 `vendor_disabled` 调度保护；恢复只解除该保护，不清除无凭据、手动暂停、冷却等原有保护。停用一级同时保护直属下级；父级停用时下级不能继续开户。资源配额将直属下级占用计入父级上限，不能通过创建多个子供应商绕过父级总额度。

## 结算规则和边界

金额 = 官方价 USD 用量 × 合同采购单价 CNY/USD × 倍率 ÷ 汇率 CNY/USDT，四舍五入至 6 位小数。合同参数更新创建新版本，历史合同和账单不改写；跨合同变更的周期须拆分，初始合同可用于已有留存历史用量。

同一付款边重复生成同周期返回原单，非作废周期之间不能重叠。预览金额/合同版本发生变化时不能直接提交旧预览。确认后允许分次登记已付款金额；付款键幂等、超付拒绝。零金额账单确认后直接结清。已部分付款或已付款账单不能作废；同合同同周期已作废记录不能被覆盖或重新生成。所有操作保留审计。

付款登记只记账，不连接支付渠道、不向币安转账。本轮不增加自动付款、退款/冲正或跨方代付。现有供应商分组单价档案保持原字段，本轮结算使用合同中明确保存的统一采购单价、汇率和倍率，不声称已实现 sub2api 的全部分组阶梯定价能力。

原账号池实时额度/Token/消耗继续依赖已采集的 VM 用量快照，未知显示“—”；期间财务统计使用已记录请求。日志关闭、升级前已删除的日志、网关外请求和未记录的失败上游消耗不纳入本轮用量。供应商事实按记录时价格保留，普通日志重新定价不会回写已保存事实或结算快照。

## 接口与升级

保留 `/api/admin/vendors` GET/POST、`/:id` PATCH，增加 `/:id` GET。新增以下 14 个路径模板（加上既有详情路径的 GET，共 22 个新增方法/路径组合）：

- `/api/admin/vendors/accounts` GET/POST，`/accounts/:id` GET/PATCH/DELETE，`/accounts/:id/pause` 与 `/resume` POST。
- `/api/admin/vendors/proxies` GET/POST，`/proxies/:id` GET/PATCH/DELETE，`/proxies/:id/pause` 与 `/resume` POST。
- `/api/admin/vendors/usage` GET。
- `/api/admin/vendors/settlements` GET/POST，`/settlements/preview` POST。
- `/api/admin/vendors/settlements/:id/confirm`、`/payments`、`/void` POST。

资源 PATCH 允许 name/status，不允许通过内部 VM 映射转移归属。超管创建供应商新增 username/password 原子创建形式；已存在的 user_id 绑定仅允许未绑定供应商的普通用户或供应商角色，禁止把管理员绑定为供应商。

无新增运行配置、依赖或 SQL Schema 迁移；部署前后端后生效。沿用现行主线 1.4.026（另一任务已交付的上游同步），本任务不附带同步上游、发版、部署或生产数据操作。

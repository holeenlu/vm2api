# 实施拆分与验收计划

## 1. 实施原则

先建立领域和授权事实，再接入页面和门户；每个工作包都要有数据迁移、接口、前端、审计和验证边界。旧 `admin/super/user` 经 047 迁移为 `super_admin/admin/user`，权限按 [最新角色与菜单决定](09-menu-and-role-plan.md) 收紧；供应商能力通过新范围模型接入，避免在旧 `user` 分支中堆叠供应商例外。

## 2. 工作包

| WP | 交付物 | 依赖 | 完成标准 |
|---|---|---|---|
| WP01 | 角色/能力目录和兼容映射 | 无 | SA/AD/U 普通面板职责已调整；V1/V2 身份与 scope 待实现；角色命名和旧会话升级兼容已处理 |
| WP02 | vendor、member、scope、grant 数据模型 | WP01 | 迁移可重跑、唯一约束、父子树约束和软删除明确 |
| WP03 | 供应商认证和范围中间件 | WP01/02 | 自有、直属聚合、跨树、停用、撤销竞态均有测试 |
| WP04 | 供应商账号/代理/用量 API | WP03 | 列表、详情、写入、导出只返回允许投影 |
| WP05 | 下级供应商创建和策略继承 | WP03 | `vendor.create_child` 可配置；子集、额度、child limit、幂等和审计通过 |

## 3. 最小验收矩阵

### 角色和范围

- 超级管理员可创建、停用、恢复一级供应商并查看全局聚合；
- 超级管理员可以创建和管理平台 VM；
- 管理员只能创建、停用、改密和删除 U，并查看 U 的使用记录、统计和账单；
- 用户只能创建和管理自己的 API Key，并查看自己的使用记录、统计和账单；
- 一级/二级供应商可以创建和管理自己的账号、VM、代理，并查看自己 VM 的使用状况和统计；
- 用户不能创建或管理 VM；
- 一级供应商只能读自己和直属下级允许的聚合，不能越级写入；
- 二级供应商不能创建供应商，不能读取兄弟或父级的完整资源；
- 缺少 `vendor.create_child` 的一级供应商创建请求得到稳定 403。

### 下级供应商开户

- 正常创建二级供应商成功并写入 member、policy、audit；
- 超过 `child_limit` 失败且无半成品；
- groups/platforms 超集失败；
- account/proxy limit 超额失败；
- 并发相同请求只产生一个有效子级；
- 父级停用、权限撤销或 revision 过期时拒绝；
- 不能创建三级、跨 root 或修改 root。

### 资源和凭据

- 供应商只能管理自有账号、代理和授权；
- V1/V2 的 VM 创建请求不经过普通 `user` 面板 ACL，必须带供应商身份和供应商资源范围；
- 归档后资源只读，历史用量和账单不丢；
- 授权撤销、供应商停用和分组移除在真实派发前生效；
- 列表、详情、导出都不泄露 token、密码和其他供应商资料；
- 异步刷新使用 owner/revision/claim，旧任务不能覆盖新状态。

### 结算

- 同一 usage fact 在每条合同边各结算一次；
- 平台→一级与一级→二级互不串账；
- 合同变更不重算历史账单；
- 重复确认、重复付款、冲正和调整单幂等；
- 金额精度、汇率、倍率和快照可由结算行重建；
- 未确认或未知状态不被伪装成已付款。

## 4. 验证层级

| 层级 | 内容 | 证据 |
|---|---|---|
| U | 能力解析、层级约束、金额公式、状态机 | 单元测试和不变量测试 |
| S | handler、repository、事务、并发和范围投影 | 集成测试、竞态测试、迁移测试 |
| E | 独立门户、真实登录、跨 origin、错误码和页面 | 受控浏览器/容器验收 |
| P | 指定部署 SHA、配置 revision、真实账号和实际拓扑 | 明确授权后的线上验收记录 |

本地替身、静态路由注册或页面按钮只能证明相应层级，不能代替真实供应商账号、真实存储、真实上游或生产验收。

## 5. 发布闸门

- 迁移前有可验证备份，迁移文件不可改写已发布历史；
- 旧面板角色和 owner 行为通过现有测试；
- 新供应商范围测试覆盖跨树、父级停用、能力撤销和并发；
- 审计事件、敏感字段投影和导出保护通过；
- 结算对账和幂等恢复通过；
- 门户镜像和后端 API 版本匹配，健康检查不冒充业务健康；
- 发现数据归属、账务或权限不确定时停止发布，不用默认值猜测。

## 6. 回退边界

代码回退不能自动回滚已经产生的供应商账单、付款流水或审计事实。迁移应优先采用向后兼容字段和双读窗口；若必须回退，先停止新供应商写入，导出受影响范围，按账务和资源事实单独修复，最后再恢复入口。

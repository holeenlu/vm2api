# 菜单信息架构与角色职责

日期：2026-10-29。依据本轮用户明确的 SA/AD/U/供应商职责，供应商只有一个登录角色；一级/二级是供应商主体层级，取代此前把 V1/V2 作为登录角色的设计。

## 1. 角色与兼容编码

| 业务身份 | 目标名称 | 当前普通面板存储编码 | 责任 |
|---|---|---|---|
| SA | 超级管理员 `super_admin` | `super_admin`（旧 `admin` 迁移而来） | 创建和管理平台账号/VM、用户/管理员、平台资源和系统配置；治理供应商 |
| AD | 管理员 `admin` | `admin`（旧 `super` 迁移而来） | 创建、启停、改密和删除普通 U，查看 U 的使用记录和统计；不操作 VM、供应商资源和系统配置 |
| U | 用户 `user` | `user` | 创建和管理个人 Key，使用模型，查看自己的使用记录、统计和账单 |
| 供应商 | 供应商 | `vendor` | 创建和管理自己的服务提供商账号/VM；查看自己的用量；勾选 `vendor.create_child` 后可创建直属二级供应商 |

这里的“SA 才能管理 VM”指普通平台身份 SA/AD/U 中只有 SA 有该能力。供应商 `vendor` 在独立的供应商业务范围内管理自己的账号/VM，主体 tier 决定是否处于一级或二级层级。资源不能因为共用 VM 实现而跨供应商或转成普通 U 的管理权限。

数据库迁移 `054_panel_role_names.sql` 将旧 `admin` 转为 `super_admin`，旧 `super` 转为 `admin`。迁移 `057_supplier_login_role.sql` 将已有供应商成员统一标记为 `vendor`。新用户角色为 `super_admin/admin/user/vendor`；供应商主体的 `tier=1/2` 不进入角色下拉框。

AD 目前管理所有普通 U；本轮没有新增“仅自己创建的 U”的归属约束。如果后续限定管理范围，必须增加可信 `created_by` 或显式委派关系，并在查询分页之前过滤；不能由前端筛选代替。

右上角保留唯一账号入口（含个人资料 `/profile`），左下角账号菜单和上游 GitHub/文档按钮继续保持移除；顶部名称、Logo 和 favicon 由品牌设置提供，默认 tapmodels。

## 3. 导航行为

- 未指定有效授权回跳页面时，SA 进入 `/overview`、AD 进入 `/users`、U 进入 `/keys`、供应商进入 `/vendor`；品牌链接通过根路由回到当前身份的允许入口。
- 工作台已按用户要求移除；平台、用户运营和个人使用功能通过现有侧栏访问，安装引导保留 `/welcome`。
- 侧栏、命令搜索和路由进入检查都使用认证后端返回的 `views`。
- 访问无权限的书签或登录重定向目标时，返回当前角色第一个允许页面。
- U 的历史自建 VM 配额不再授予创建权限；用户表单移除该配额输入。
- AD 的表单不允许选择 SA/AD 角色；后端仍拒绝伪造角色提升和受保护目标的操作。
- AD 的统计只允许 `user/model` 维度，不显示 VM 或供应商排行。
- AD 的日志、导出、会话建议、账单和汇总采用普通 U 消费归属过滤；不通过供应 VM owner 反推消费者。供应 VM 属于 U，也不能让 AD 看见该 VM 上 SA/AD 的请求。
- 保留定制版商业分组和 Key 连接配置契约；U 使用获授权分组和个人套餐，不开放 VM 清单、详情或写操作。

## 4. 供应商门户菜单合同

| 类别 | 菜单 | tier=1 | tier=2 |
|---|---|---|---|
| 运营管理 | 我的资源概览、使用记录、VM 用量统计 | 自有范围 | 自有范围 |
| 运营管理 | 下级供应商 | 仅在 `vendor.create_child` 存在时显示；创建直属二级供应商 | 无 |
| 统计 | 账单 | 上游对账单；一级可新增并查看下游结算 | 只读上游对账单 |
| 资源管理 | 账号池、VM、IP 代理、授权导入 | 自己；账号/VM 允许创建 | 自己；账号/VM 允许创建 |
| 运营管理 | 操作记录 | 当前供应商允许范围 | 自有范围 |
| 系统管理 | 平台集群、平台内核、数据库、全局设置 | 无 | 无 |

供应商拥有 VM 操作能力，不代表拥有宿主机、集群节点、内核发布、数据库维护、任意终端或文件操作能力。供应商 VM API 必须采用允许的字段和动作列表，复用底层创建用例，不能直接开放完整 SA 路由。

## 5. 交付边界

普通面板职责、菜单、页面进入检查、供应商角色、供应商门户和服务提供商运营视图在本轮代码中落地；结算深度能力仍按既有接口边界逐步扩展。新增角色迁移 057；未改动历史迁移，不变更资源和账务归属。`docs/PANEL_API.md` 记录普通面板现状，本文件记录本轮的角色及菜单决定。

## 6. 角色迁移的升级与回退边界

054 只转换角色值；用户 ID、密码、状态、余额、Key 和资源归属保持不变。已有停用和软删除记录也转换命名，保持历史解释一致。迁移器记录 054 已执行，重复启动不会把新的 `admin` 再升级为 `super_admin`。

新旧版本对 `admin` 的语义不同，因此迁移后不能直接启动旧服务代码。需要回退时先停止写入，再恢复升级前备份和匹配的旧代码；如果必须保留升级后的新增数据，应先设计并验证反向角色转换及会话失效方案。仅回滚前端或 Git 提交不能视为数据回退完成。

本机验收会先备份并在数据库副本验证，再更新当前已授权的本机 Docker。生产数据库和生产部署不在本轮范围内。

# 供应商平台实现与验收记录

## 本次实现

- 新增供应商、成员、能力、资源、审计和用量事实的数据模型与 `056_supplier_platform.sql` 迁移。
- 新增 V1/V2 层级和能力校验：`vendor.create_child` 决定是否显示和允许使用下级供应商入口。
- 新增 `/api/vendor/*` 供应商接口和 `/api/admin/vendors/*` 超级管理员接口。
- 供应商新增账号时提交平台、授权方式、代理、区域、语言和运行环境等参数；后端自动创建账号资源、配对 VM 资源和运行时 VM 文件。
- `POST /api/vendor/vms` 明确拒绝直接创建，返回 `account_creation_required`。
- 新增 `/vendor` 门户页面。页面根据 `/api/vendor/me` 的 `views/capabilities` 渲染菜单；没有下级供应商能力时不显示“下级供应商”。
- 供应商门户按 sub2api 供应商平台的工作台结构整理为“资源 / 统计”分组，账号池提供概览卡、平台/状态筛选、账号与 VM 绑定展示；新增代理管理、账号池和 IP 代理的供应商范围筛选。
- `child_limit=0` 表示直属二级供应商数量不限制；账号池和 IP 代理供应商筛选接口仍要求一级身份和 `vendor.create_child` 能力。

## 本轮 UI 对照验收与范围（2026-10-29）

参考 sub2api 本地 HEAD `0276190e775b369319acc18bc1c120a4469a71ae`。本轮已完成独立路由、侧栏、真实状态/额度/消耗投影、筛选分页、手机导航和能力控制；未完成完整 OAuth 向导、批量导入导出、代理质量检测及结算写入，不能把本轮 UI 验收算作供应商平台全功能验收。

验证：后端 vendor-platform + vendor-portal-view 13 项；前端 portal-model 2 项；Linux 容器真实 HTTP 2 项。HTTP 覆盖零上限、两个下级创建、父级只读、子级无下级权限、GET 不改变状态、暂停后恢复不解除无凭据限制。测试使用临时数据库和替身上游，不调用付费推理。

本机 Docker Desktop 原生 ARM 控制面无法执行固定 amd64 kin-computer；本轮本地 compose 覆盖指定 linux/amd64，沿用项目固定 payload，不以隐藏错误或跳过计算机身份校验冒充运行成功。前端测试实例使用独立 8788 容器，不写 8787 业务数据库。

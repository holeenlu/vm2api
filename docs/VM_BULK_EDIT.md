# 虚拟机批量编辑

实施日期：2026-11-02。入口：资源管理 → 虚拟机。

## 操作

列表和机架共用勾选结果，支持全选当前筛选结果，最多 500 台。排序、轮询和视图切换保留选择；改变搜索、状态、平台、供应商或分组筛选会清空选择。消失的记录从选择中移除。只对超级管理员开放。

选择后只有一个「批量编辑」入口。弹窗为单页，所有字段按顺序显示，分组位于底部，不设页签。每项默认不修改；只提交勾选项，当前值不同会展示其取值。最大并发 1–256、RPM 0–1000000（0 不限）、GPT 权重 1–100、Claude 等级 1–10；明确选择恢复默认/自动才清除覆盖。调度开关仅操作人工开关，不清理凭证、额度、冷却或供应商限制。

分组可追加、移除或替换，默认追加；混合平台先通过「仅 GPT / 仅 Claude」缩小本次全部字段的目标范围。组卡显示当前成员数和启用状态。保留现有后端的 mixed/claude/anthropic/openai 及执行后端匹配规则；停用组可按既有契约管理，不改变其停用状态。替换为空或移除最后一个分组，在原表单内明确确认后果。

点击「保存」直接提交，没有预览页、二次提交和成功结果页。服务端确认全部适用字段已保存（或无变化）后自动关闭，清除成功目标的选择，刷新列表并提示。保存成功但刷新失败单独提示，不重试已经成功的写入。失败保留表单、草稿与具体结果；关闭未保存草稿有放弃确认。

## 持久化与重试

- 分组继续写 SQLite，沿用版本检查与全批事务。调度配置通过原有 VM 持久化方法更新记录和运行态；不为批量 UI 重建另一套调度存储。
- 新迁移 `076_vm_bulk_edits.sql` 增加操作记录表；按操作编号、操作者、请求摘要和每台每字段的结果去重，不存凭证。
- 保存前对整批目标做权限、归档、平台、数值、分组版本、待改字段摘要、供应商及凭证状态校验。预测得到的错误在写入前拒绝。
- 分组变更与其成功记录在一个 SQLite 事务中提交，分组失败不执行后续字段。调度字段先记录 `writing`，调用已有持久化/运行态方法，再写审计与成功记录。文件与数据库之间不承诺全批原子回滚。
- 响应为 `complete` 或 `incomplete`，逐字段为 `saved`、`unchanged`、`not_applicable`、`pending`、`writing`。`writing` 表示写入结果未确认，不等于没有写入。
- 断线先查询同一操作编号，再用原请求重试。已成功字段不重放；未确认字段仅在当前值仍等于原值或目标值时补做运行态投影。第三方改成其他值时返回冲突。
- 同一浏览器标签的 sessionStorage 按 API 地址和登录用户名保留未确认请求（仅非敏感配置）；刷新/离开再回来可通过「继续上次保存」查询和恢复。服务端记录是结果依据。存储不可用时不阻断保存，但离开后需自行保留操作编号查询。
- 失败后可明确选择「基于当前配置重新编辑」，重新读取当前值；该操作不撤销旧命令已完成的写入。原审计和操作记录继续保留。
- 沿用本项目单进程控制面模型；命令校验与写入之间不跨 await。没有新增多进程分布式锁、后台恢复任务或自动回滚。

## 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/panel/vms/bulk-edit/snapshot` | `{ids}`，返回编辑值、字段摘要与分组版本 |
| POST | `/api/panel/vms/bulk-edit` | `{operation_id,items,patch,confirm_empty_groups}`，校验并直接执行 |
| GET | `/api/panel/vms/bulk-edit/operations/:id` | 查询当前操作者的持久化执行记录 |

`patch` 仅允许 `schedulable`、`max_concurrency`、`max_rpm`、`weight`、`schedule_level`、`groups:{operation,ids}`。数值 `null` 表示恢复默认；省略表示不修改。GPT 权重和 Claude 等级分别只作用于所属平台。请求体最多 1 MiB；目标最多 500 台。

旧 `vm-batch-groups.tsx` 以及其四语专属文案已删除。现有单台分组与 `/vms/groups/batch` 接口保留并共用平台/后端校验；它们仍是已文档化的分组 API 和既有回归入口。单台编辑、全局策略页使用的 `/vms/pool-policy` 不被替换。

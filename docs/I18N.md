# 控制台国际化

## 语言与状态

前端使用 i18next + react-i18next。资源目录为 web/src/i18n/locales/<BCP47 locale>/<namespace>.json，支持 en-US、zh-CN、zh-TW、ja-JP，namespace 对应业务模块；common 用于公共控件，lib 用于共享呈现函数。zh-TW 使用台湾繁体中文用语，例如「設定、儲存、使用者、伺服器、資料、連線」。

初始化先读取 tapmodels.locale；兼容本产品已经保存的 en_US、zh_CN、zh_TW、ja_JP，随后由 LocaleProvider 写回标准连字符 ID。没有偏好时匹配浏览器语言，不能识别时回落 zh-CN。此读取兼容仅针对已发布的同一偏好键，不引入旧品牌存储或 VM locale 迁移；待已保存偏好迁移完成后可移除下划线解析。HTML lang 与偏好同步。存储被禁用时仍能切换，不抛异常。

组件使用 useTranslation(namespace) 订阅语言变化；组件外通知、格式化等通过 @/i18n 导出的 t 在调用时取当前语言。LocaleProvider 保持组件树身份，不用 locale 作为页面 key，因此切换语言不会清空草稿。

台湾繁体中文与日文的语境、专业术语和审校边界见 [术语约定](I18N_TERMINOLOGY.md)。

## 新增文案

- 使用稳定的英文语义键，不把整句中文、哈希或编号当键。每次变更同步四语同一 namespace。
- 翻译完整句子，变量使用 {{name}}，不要拼接语序相关的片段。保留原始业务值，只翻译呈现文字。
- 含数目的句子传 count，按语言使用 i18next JSON v4 的 _one、_other 等复数形式；同一消息各语言的插值变量必须一致。
- 包含链接、加粗等 React 节点时使用 Trans 与命名 components 插槽，不注入 HTML，不使用 dangerouslySetInnerHTML 展示译文。普通文本交由 React 转义；i18next 不再重复 HTML 转义。
- 不在模块加载时调用 t 固化标签。静态枚举存语义键，或通过 getter/函数在读取时翻译；useMemo/useCallback 必须包含影响译文的 t/语言依赖。
- 页面只翻译自己的文案。PageHeader、选择器等通用组件直接显示调用者传入的内容；禁止对用户输入、模型名、地址或 API 字段进行“自动翻译”。
- 保留协议值和原始日志。已知状态使用稳定代码定位译文，不能比较本地化显示文本来决定调度、权限、筛选或保存行为。
- 日期数字使用 Intl 与当前 resolvedLanguage；保留明确设置的时区和结算币种。界面语言与槽位 LANG/LC_ALL/TZ 是独立配置。

## 验证

在 web 目录运行 pnpm test:i18n、pnpm test、pnpm typecheck、pnpm build，并对受影响文件运行 ESLint 和 Prettier。

coverage.test.ts 检查四语 namespace、键、非空值、插值、富文本插槽、静态键引用和用户可见硬编码；它作为完整 Vitest 套件的一部分进入现有 CI。商标、协议缩写、单位及请求代码由 invariant-copy.ts 中有理由的精确不变量分组及格式规则识别；特定位置确实不应翻译的文本，使用紧邻节点的精确 i18n-exempt 注释，写明原文与理由。不能添加普通界面文案来绕过检查，不允许按目录或历史基线豁免全部文案。动态键另外通过模块测试覆盖。

浏览器验收至少覆盖：四语切换与刷新保留，模型页及弹窗、创建/编辑槽位、设置与登录，未保存表单不丢失，英文页面无残留内置中文，台湾繁体用语，长译文在窄屏布局不溢出，控制台无缺失键或运行异常。后端返回的原始诊断和用户录入内容不计作遗漏翻译。

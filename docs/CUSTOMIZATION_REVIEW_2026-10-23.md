## 历史发现（以下五项已修复）

### R1 [P1] 在异步资格检查结束及排队授予席位时重新核验授权

位置：`src/lib/pool/pool-scheduler.mjs:877–900`（定制新增的 scope 刷新）。资格检查只在 `await checkEligibility()` 之前刷新 Key/分组状态；检查结束后仍使用旧 scope 生成候选并分配容量。`selectSeat()` 的缓存 ticket 授予路径同样直接返回已有候选。管理员在健康检查或排队期间停用 Key、撤销组资格或移除资源后，请求仍可能派发。

隔离复现使用内存 SQLite、临时 VM 和可控 workerHealth：在健康检查返回前把 Key 设为 disabled，`selectAndReserve()` 仍返回 `ok:true` 和该 VM。没有发送真实推理。修复应在最终同步授予/派发处核验当前 Key、组、模型和资源，拒绝时释放已占容量；回归覆盖健康检查 await 和队列唤醒两种时序。

### R2 [P1] 在 GPT 重选和 API 派发时复核最新模型白名单

位置：`src/lib/protocol/handle-codex.mjs:218–221`；关联 `src/lib/pool/api-protocol.mjs:155–157`。入口 handle-protocol 只检查一次模型权限。GPT 排队/故障转移重新读取 scope 时，只检查分组可用性和 VM 资格，没有重新调用 keyAllowsModel；API 派发也只使用 allowed_endpoints。请求等待期间从组白名单删除该模型后，仍可能按原请求派发。

隔离复现：组起初允许 gpt-6.1-sol，改为仅允许 gpt-6-astra；`keyAllowsModel()` 返回 false，而 `pickCodexCandidates()` 仍返回该 GPT 槽位。修复应让所有执行后端在最后准入处使用同一模型授权判断，覆盖队列唤醒及重试，而不是只测试 scope 读取函数。

### R3 [P2] 接受管理员明确提交的空分组

位置：`src/lib/admin/api-keys.mjs:272`。Key 编辑界面选择“站长自用”会发送 `group_id:null`；路由允许管理员这样修改，但 Store 的 `patch.group_id != null` 条件会忽略这次修改。保存返回成功，Key 却仍绑定旧商业组，继续受组模型、资源和停用状态限制。

内存数据库复现：已绑定 group_id=3 的 Key 执行 update({group_id:null}) 后仍是 3。应区分未传 group_id 与明确传 null，并保留客户 Key 必须关联授权组的路由校验。

### R4 [P2] 为 HTTP 控制台提供可用的账务幂等标识生成方式

位置：`web/src/features/users/index.tsx:98`、`:194`。项目部署文档支持 `http://<ip>:8787`，而用户管理新增的余额入口及所有保存成功回调直接调用 crypto.randomUUID。普通 HTTP IP 页面没有该 API：余额对话框无法取得有效幂等标识；新建/编辑/删除用户即使后端成功，成功回调也会抛错并跳过列表缓存刷新。

此项依据实际调用链与浏览器 API 契约，未声称已在生产浏览器复现。[MDN randomUUID 文档](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID) 明确其安全上下文限制。应使用允许 HTTP 的安全随机字节生成幂等标识，保留同一操作重试时标识稳定，并测试 randomUUID 不存在的页面环境。

### R5 无可用供给告警（2026-10-31 已随功能撤销）

历史问题为独立运维快照只统计 VM，遗漏 API 资源。该功能曾补充供给检查，现按用户要求整项移除，专属聚合、供给检查方法及对应测试均已删除；不再作为待修复项或保留实现的依据。
